# Shared form page UI

Enable the components in the consumer's existing create or edit templates. Load
the CSS bundle from the page's rendered content and append
`auscope-core-form-page` in CKAN's `wrapper_class` block. The class styles CKAN's
existing primary and secondary columns and sidebar heading. It keeps the
sidebar beside the form on desktop and stacks the columns in document order
below the CKAN medium breakpoint. The Core form groups bundle can be used
independently on the same page.

```jinja
{% asset 'auscope_core/auscope-core-form-page-css' %}
{% from 'snippets/auscope_core/form_page.html' import
    form_header, form_stages, form_navigation, form_actions with context %}

{{ form_header(_('Deposit data'), _('Describe the dataset and its files.')) }}

{{ form_stages([
  {'label': _('Metadata'), 'state': 'completed', 'url': metadata_url},
  {'label': _('Files'), 'state': 'active'},
  {'label': _('Review'), 'state': 'upcoming'},
]) }}
```

- `form_stages(stages, label=none)` accepts an ordered list of stage mappings.
  Each mapping has a localized `label` and a `state` of `active`, `completed`
  or `upcoming`. Omit a state to show it as upcoming. Supply at most one active
  stage and pass an empty list to omit the indicator. A stage is static unless
  it has a consumer-generated `url` or a `submit` mapping with `name` and
  `value`. Use one control per stage and render stage submit buttons inside the
  existing form. Only include enabled and authorized destinations. The current
  stage is marked with `aria-current="step"`. Completed stages have a check
  mark and a screen-reader status. Multi-stage rows wrap at desktop widths and
  stack at narrow widths.
- `form_header(title, description=none, actions='', navigation='')` renders the
  page's H1, optional description, and optional rendered action and navigation
  markup. Render it once per page.
- `form_navigation(label)` is a call block for native `li` elements containing
  links. Give the navigation landmark a localized label and set
  `aria-current="page"` on the current link. Core also styles the `.active`
  list item generated by CKAN's navigation helpers. Empty navigation is omitted.
- `form_actions(primary='', secondary='', description='')` accepts rendered
  markup for the action groups and supporting text or disclaimers. Keep buttons
  in the existing form and use CKAN's usual `btn` classes. The secondary
  actions appear first in document and keyboard order. The primary actions
  align to the end and wrap as needed. Capture slots with Jinja block
  assignment or pass the output of an existing block. Plain strings are escaped.

Core supplies markup, layout and its existing colours and focus styles.
Consumers own localized copy, step state, form and route selection, field
rendering, action placement within each group, permissions, validation,
CSRF, submit names and values, and persistence. No JavaScript is needed for
these components. A consumer that also supports older Core wheels can guard
its imports and asset tag with `'auscope_core_form_page_available' in h` and
delegate to the original CKAN or Scheming block when the capability is absent.

## Adopting in other registries

- **Data** can adapt the current Scheming pages and CKAN resource stages to
  the list contract. It can retain its draft checks, metadata and resource
  destinations, and native postback buttons inside its existing form.
- **Sample** can supply its existing single creation stage and place Finish
  and Save & add another in shared action groups. Collection and collaborator
  permissions stay in its templates.
- **PIDINST** can share the presentation of its stage and action row while
  retaining lifecycle actions, Cancel, Save and exit, and Save & add
  attachments, including its existing return targets and submit values.

RAiD is the initial consumer on CKAN 2.12.1 with Scheming 3.1.0. Verify template
block and asset compatibility in each older CKAN stack before adopting.
Confirm mobile layout and keyboard order with the repository's real stage
names, field widgets and button sets.
